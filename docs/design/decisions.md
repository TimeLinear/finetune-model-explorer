# 결정사항 요약

> 이 프로젝트의 설계 결정 기록. 개발에 필요한 결정만 추렸다. 전체 배경은 README 참고.
> 2026-10-23 기준

## 범위
- **D-01 개발 단계:** 1단계(필수 F2001~F2012) 완성 전에는 2단계(리서치) 착수 금지. 심화는 F2016(출처 결합), F2014(MMR).
- **D-02 리서치 기능은 별도 모듈·별도 페이지.** 기본 질의응답 파이프라인은 리서치 기능 변경에 영향받지 않아야 한다.
- **D-03 리서치 주제:** 도메인 맞춤 파인튜닝 후보 선별 + 근거 제시 (2단계, 이번 개발 범위 아님).

## 도메인과 데이터
- **D-04 도메인:** 파인튜닝용 오픈 웨이트 언어 모델. 공식 조직 계정만, 1~24B, 베이스+인스트럭트, 한국 모델·멀티모달·특수 목적 모델 포함.
- **D-05·D-06 항목 목록:** `data/items_20261021.json`(202개, 2026-10-21 스냅샷 고정). **이 파일은 수정하지 않는다.** 보강 결과는 별도 파일에 저장한다.
- **D-07 항목 설계 원칙**
  - 아키텍처·컨텍스트 길이는 기계 판독 출처만 쓴다 (`context_source`로 출처 표시: `config.json` / `library_default` / `not_applicable`).
  - 모델 소개 요약은 카드 기반 LLM 요약. **`card_url`, `card_revision`, 생성 일시, 생성 모델명을 반드시 함께 저장.**
  - "상업적 이용 가능 여부" 판정은 저장하지 않는다. 질문 시점에 원문 근거로만 답한다.
  - 항목 ID = Hugging Face 저장소 ID (`조직/모델명`). 바꾸지 않는다.
  - 필드 목록은 코드에 박지 않고 스키마·설정으로 관리 (NF2005).
  - 이름 규칙으로 추정한 값은 `stage_needs_review`, `modality_needs_review`로 표시돼 있다.
- **D-08 지역·언어 확장 원칙 (지금부터 지킨다)**
  1. 데이터에는 코드값만 (국가 ISO 3166, 언어 ISO 639, 분야 영문 코드). 표시 이름은 언어별 라벨 파일.
  2. "우선 지역"은 설정값.
  3. "한국어 지원 여부" 같은 판단은 저장하지 않고 계산.
  4. 생성 텍스트는 언어 코드를 키로 저장 (예: `summary.ko`).
  5. 색인 텍스트 언어(`INDEX_LANG`), 프롬프트 응답 언어, UI 문구, 면책 문구는 언어별 파일·설정.
  6. 청크 메타데이터에 `doc_lang`.
  7. 날짜는 ISO 형식으로 저장, 표시 형식은 화면에서.

## 갱신 정책 (O-06)
- MVP는 스냅샷 고정. 최종 방향은 "진입·퇴출 기준 분리 + 사용 중 모델 보존", 퇴출은 삭제가 아니라 `status=archived`. MVP에서는 구현하지 않는다.

## 모델·API
- LLM은 작업별 설정 키(`LLM_SUMMARY`, `LLM_SMALL`, `LLM_ANSWER`)로 제공사·모델을 고른다. 모델 이름을 코드에 넣지 않는다.
- LangChain 채팅 모델 추상화 + `with_structured_output` 사용 (GPT·Claude 공통).
- **임베딩은 로컬 모델** (`BAAI/bge-m3` 1순위). 이유: 초기 API 프록시는 기간이 정해져 있었고, Anthropic은 임베딩 API가 없음.
- 초기 개발 단계(2026-10-23까지)에는 OpenAI 호환 API 프록시를 거쳐 GPT·Claude 모델을 호출했다. 이 기간 안에 **모델 소개 요약 202개를 Sonnet급으로 생성했다.** (완료)
- 2026-10-23 API 프록시 사용을 마치고 Anthropic API 직접 호출로 전환했다. 현재 `config/llm.json`에는 `anthropic_direct` 프로필만 있다 (아래 "네트워크·비밀 값").
- 답변 생성 모델은 `claude-haiku-5-5`로 확정 (F2015 비교 근거, [models.md](models.md)).
- 카드 머리말 색인, 저가치 섹션 제외, 색인 규칙 버전은 [collections.md](collections.md) 3절 "카드 머리말과 섹션 처리" 참고.

## 저장소에 올리는 데이터 범위 (2026-10-22)
- **모델 카드 원문(`data/cards/`)과 Chroma 색인 폴더는 저장소에 올리지 않는다.**
  - 게이트 저장소 카드는 라이선스 동의를 거쳐야 볼 수 있는 내용이라, 저장소에 올리면 그 절차를 우회해 재배포하는 셈이 된다.
  - 공개 카드도 저작권은 올린 조직에 있고 이용 허락은 Hugging Face 서비스를 통한 이용 범위다.
  - Chroma 색인에도 카드 본문 청크가 들어 있으므로 같은 이유로 제외한다.
- **재현성은 "리비전 고정 + 다시 받기"로 보장한다.** `data/cards/manifest`(모델 ID, 카드 리비전, URL, 본문 해시, 길이)는 올린다. 다른 사람이 clone하면 `scripts/fetch_cards.py`가 같은 리비전의 카드를 받아 해시로 동일성을 확인한다 (게이트 모델은 각자 라이선스 동의 필요).
- **모델 소개 요약(`data/summaries.jsonl`)은 올린다.** 우리가 생성한 짧은 파생 텍스트이고, 카드 URL·리비전으로 출처를 남기며, 다시 만들려면 202개 전체를 다시 요약해야 하기 때문이다.

## 화면 (2026-10-22)
- MVP 화면은 Streamlit으로 완성·검증한다. F2013(HTML/CSS/JS + FastAPI)은 Streamlit을 대체하지 않고 **추가**하며, 필수 기능 검증과 F2015를 마친 뒤 착수한다. ~~디자인은 시안을 먼저 만든 뒤 구현한다.~~
- **F2013 진행 (2026-10-23):** 시안 단계를 따로 두지 않고 구현 결과를 첫 시안으로 삼았다. `web/`(FastAPI + 순수 HTML/CSS/JS, 빌드 도구·CDN 없음)로 질의응답·점검표·조건 탐색·리서치 안내 화면을 만들고 디자인을 한 차례 다듬어 master에 병합했다. 서버는 대화 상태를 갖지 않고 대화 기록은 브라우저에 둔다. 127.0.0.1에만 바인딩. 이후 화면 수정은 이 시안을 기준으로 한다.
- highlights는 원문 그대로 저장하고 화면에서만 말줄임 처리한다 ([retrieval-and-ui.md](retrieval-and-ui.md) 참고).
- `logs/`는 저장소에 올리지 않는다.

## 네트워크·비밀 값
- 필요 도메인: `huggingface.co`, `*.hf.co`, `ko.wikipedia.org`, `api.anthropic.com`
- `.env` 키: `ANTHROPIC_API_KEY`, `HF_TOKEN`, `WIKI_CONTACT`. 값은 출력·로그·커밋 금지.
- LLM 호출 프로필(`config/llm.json`의 `active_profile`): **`anthropic_direct` (2026-10-23 전환, 유일한 프로필)**. 작업 3개 모두 Claude, `LLM_SMALL`·`LLM_ANSWER` = Haiku. 초기 단계에 쓰던 API 프록시 프로필은 삭제했다. 직접 호출은 개인 크레딧이 들므로 시험 호출도 횟수를 정해서 한다.
- 게이트 저장소(Llama·Gemma 등)는 `HF_TOKEN`으로 조회 (라이선스 동의 완료).
