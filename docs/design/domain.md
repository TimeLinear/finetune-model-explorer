# 도메인 확정 근거

> 이 도메인이 RAG(검색 증강 생성)에 맞는 이유를 정리한다. 상세 결정 과정은 [decisions.md](decisions.md) 참고.
> 작성: 2026-10-21

## 도메인

**파인튜닝용 오픈 웨이트 언어 모델** — 공식 조직이 Hugging Face에 공개한 약 1~24B 규모 언어 모델(멀티모달 포함) 202종을 다룬다. 사용자는 모델별로 질문하거나, 자신의 업무 조건에 맞는 파인튜닝 후보 모델을 근거와 함께 찾는다.

## 1. 구조화된 항목 메타데이터를 충분히 모을 수 있다

검색과 필터의 기준이 될 항목 목록을 기계 판독 출처에서 일관되게 만들 수 있다.

- 출처: Hugging Face Hub API (모델 정보), 각 저장소의 `config.json`, 필요 시 `transformers` 설정 클래스 기본값
- 건수: **202건** (2026-10-21 스냅샷 고정)
- 선별 기준: 공식 조직 계정, 1~24B, 최근 30일 다운로드 기준 그룹 내 상대 순위
- 파일: `data/items_20261021.csv`, `data/items_20261021.json`

## 2. 항목마다 연결되는 외부 문서가 있고 이용 조건이 분명하다

모든 항목에 모델 카드라는 1:1 원문 문서가 있어, 답변 근거를 항목 단위로 찾고 원문 링크로 제시할 수 있다.

| 출처 | 용도 | 이용 조건 | 지키는 방법 |
|---|---|---|---|
| Hugging Face 모델 카드 (각 저장소 README) | 주 문서 출처 (항목마다 1:1로 연결됨) | Hugging Face 이용약관: 콘텐츠 소유권은 올린 사람에게 있고, 공개 저장소 콘텐츠는 서비스를 통한 이용이 허락됨. 오픈소스 등 별도 라이선스가 붙은 콘텐츠는 그 라이선스를 따름. 저장소별 라이선스는 항목의 `license` 필드에 기록 | 청크마다 원문 URL과 카드 리비전(커밋 해시)을 저장하고 근거 표시 시 링크로 제시. 카드 전문을 재배포하지 않고 근거 발췌만 표시 |
| 게이트 저장소 (Llama, Gemma 등) | 카드·설정 파일 조회 | 저장소별 라이선스 동의 후 접근. 각 모델 라이선스와 사용 정책(예: Llama 이용 정책) 적용 | 동의를 마친 계정 토큰으로만 조회. 가중치는 내려받지 않고 카드·설정 파일만 사용 |
| Hugging Face Hub API | 항목 메타데이터 | Hugging Face 이용약관 | 호출 간격(요청 사이 대기), 재시도 제한, 식별 가능한 User-Agent 사용 (NF2006) |
| 한국어 위키백과 (보조, F2016 후보) | 개념·계열 설명 | CC BY-SA 4.0 | 문서 제목과 URL을 출처로 표시. User-Agent에 연락처 포함 (위키미디어 요구사항) |

- 위키백과 User-Agent 연락처: `.env`의 `WIKI_CONTACT` 값을 사용한다 (값은 문서·코드에 적지 않는다).

## 3. 근거 없이 답하면 틀리거나 위험해지는 질문이 많다

LLM의 일반 지식만으로 답하면 그럴듯하지만 틀린 답이 나오기 쉬운 질문이 이 도메인의 대표 질문이다. 원문 근거를 찾아 붙이는 RAG가 필요한 이유다.

| # | 질문 예시 | 근거 없이 답하면 생기는 문제 | 근거 |
|---|---|---|---|
| 1 | "카카오 kanana-1.5-8b-instruct와 kanana-nano-2.1b-instruct 중 회사 서비스에 상업적으로 쓸 수 있는 건?" | 같은 회사·같은 계열이라 라이선스도 같다고 추측하기 쉽다. 실제로는 하나는 Apache-2.0, 하나는 CC BY-NC 4.0(비상업)이다. 틀리면 라이선스 위반 위험 | 항목 메타데이터 `license`, 모델 카드 |
| 2 | "EXAONE-3.5-7.8B-Instruct를 사내 업무용으로 파인튜닝해 배포해도 되나?" | 자체 라이선스(`other`)라 일반 지식으로는 조건을 알 수 없다. 추측으로 "된다"고 답하면 위험 | 모델 카드의 라이선스 조항 |
| 3 | "Gemma 3 4B-it가 한 번에 처리할 수 있는 최대 컨텍스트 길이는?" | 설정 파일에 값이 명시되지 않아 LLM이 세대·크기별 수치를 섞어 추측하기 쉽다 | 항목 메타데이터(라이브러리 기본값 + 버전), 모델 카드 |
| 4 | "Llama 3.2 11B Vision을 이미지 입력용으로 쓸 때 지역 제한이 있나?" | 모델별 이용 정책에 지역·용도 조건이 붙는 경우가 있어 일반 지식으로 답하면 틀릴 수 있다 | 모델 카드, 라이선스·이용 정책 원문 |
| 5 | "최근 공개된 ○○ 모델의 파라미터 수와 MoE 여부는?" | 학습 이후 공개된 모델은 LLM이 아예 모르거나 이전 버전 수치로 답한다 | 항목 메타데이터(`params_b`, `is_moe`, `num_experts`) |

## 위험 도메인 여부와 면책 안내

- 건강·금융처럼 잘못된 답이 바로 위험으로 이어지는 도메인은 아니다.
- 다만 라이선스·이용 정책 판단은 법률 문제에 걸쳐 있으므로 안내 문구를 둔다.
- 안내 문구: "라이선스 관련 내용은 모델 카드와 라이선스 원문을 요약한 참고 정보이며 법률 자문을 대신하지 않습니다. 상업적 이용 전에는 원문과 법무 검토를 확인하세요."
- 문구는 언어별 문자열 파일(`i18n/ko.json`)로 관리한다.
